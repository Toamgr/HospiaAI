# HESTIA Context Pack for Perplexity — v2

## Canonical Positioning

HESTIA is an integration-native Hospitality Intelligence Sidecar.

It is the private memory and judgment layer for premium hospitality teams, connected to the tools they already use.

HESTIA does not replace POS, PMS, CRM, reservations, event platforms, workforce systems, LMS tools, accounting platforms, or automation tools.

HESTIA connects to them, reads fragmented operational evidence, remembers what matters, interprets what happened, explains uncertainty, recommends next actions, and activates follow-up through the existing stack.

## One-Line Positioning

HESTIA learns from your hospitality stack, remembers what your stack forgets, explains what your stack only reports, and activates better decisions through the tools your team already uses.

## What HESTIA Is

HESTIA is:
- An integration-native Hospitality Intelligence Sidecar
- A brain layer, not a replacement system
- A private venue memory layer
- A judgment layer for owners, managers, F&B, bar, service, events, and academy teams
- An evidence-bound recommendation layer
- A confidence-aware intelligence layer
- A human-approved operational decision layer
- A premium hospitality-specific interpretation layer

## What HESTIA Is Not

HESTIA is not:
- POS
- PMS
- CRM
- LMS
- reservation system
- payment system
- event ticketing platform
- generic dashboard
- generic chatbot
- generic automation tool
- Zapier/Make with hospitality branding
- a replacement for Toast, Tabit, SevenRooms, Mews, Oracle, Tripleseat, Restaurant365, 7shifts, or LMS tools

## Core Doctrine

Guests are people we host, not customers.

HESTIA should reduce uncertainty over time, not pretend to know.

Every intelligent output should be evidence-bound, confidence-aware, and transparent about missing data.

HESTIA must avoid fake dashboards, fake certainty, invented data, generic AI summaries, and isolated features that do not feed the shared brain.

## Core Intelligence Layers

### Evidence Store

The evidence store preserves source material and provenance.

Evidence may include:
- uploaded reports
- POS exports
- Tabit reports
- shift notes
- service incidents
- guest feedback
- event history
- menus
- staff actions
- owner conversations
- operational history
- reservations data
- PMS data
- workforce data
- training records
- CRM notes

### Venue Memory

Venue Memory is selected, structured, persistent operational evidence.

It is what HESTIA remembers from fragmented systems and conversations.

### Venue Intelligence

Venue Intelligence is interpretation:
- patterns
- risks
- opportunities
- contradictions
- confidence
- missing data
- operational meaning
- recommended follow-up

### Venue DNA

Venue DNA is crystallized identity:
- service style
- taste
- values
- tone
- positioning
- founder intent
- hospitality personality
- operational standards

Venue DNA should not be created by a static questionnaire alone.
It should be pinned and updated from evidence, with meaningful changes requiring owner approval.

### Confidence Engine

HESTIA must know when it is confident, uncertain, or missing evidence.

Confidence and missing-data handling must affect recommendation behavior, not only copywriting.

### Recommendation Ledger

HESTIA should remember:
- what it recommended
- why it recommended it
- what evidence supported it
- confidence level
- who approved/rejected it
- what happened afterward

## Main Product Areas

### Owner AI Home

Owner-facing intelligence home.

It should show:
- what HESTIA knows
- what HESTIA does not know yet
- what is uncertain
- what needs owner confirmation
- what should be acted on next
- which recommendations are evidence-bound
- which recommendations require human review

### Shift Report Intelligence

The strongest first wedge.

Manual upload first.

Managers upload reports such as:
- Daily Summary
- Item Sales
- Payments
- Exceptions / voids / discounts
- KDS timing, if available
- Employees / labor, if available

HESTIA must analyze only what the reports support.

If data is missing, HESTIA must say the data is missing.

The output should surface what is working well before risks, problems, or recommendations.

Every upload should persist into Venue Memory / Business Memory, including:
- original uploaded file
- parsed facts
- calculated metrics
- insights
- recommendations
- confidence levels
- missing-data notes
- follow-up actions

### F&B Intelligence

Analyzes:
- menu performance
- sales patterns
- item performance
- taste direction
- pricing risk
- cost awareness
- operational fit
- venue positioning
- menu mix
- what is working well
- what requires owner or manager attention

### Bar Intelligence / Cocktail Intelligence

Supports:
- cocktail menu logic
- recipe intelligence
- taste profiles
- event cocktail menus
- classics vs signatures
- low/no ABV coverage
- ingredient logic
- venue-specific beverage direction
- F&B Director decision support

Taste profiles use decimal scales, not simple integers.

HESTIA should aim to create strong first/second-pass menus with minimal human trial, while still respecting human tasting, approval, and venue identity.

### Events Intelligence

Supports:
- event planning
- event CRM
- event calendar
- event overview
- event architect
- creative guest-facing menu previews
- event brief
- operational memory from past events
- learning from what worked and what failed

HESTIA should not replace event platforms such as Tripleseat or Event Temple.
It should learn from them and activate better briefs, follow-ups, and post-event learning.

### Academy Intelligence

HESTIA Academy is not a generic LMS.

Training should be:
- short
- practical
- elegant
- connected to real work
- adapted to venue standards
- adapted to Venue DNA
- based on real operational weaknesses

Academy should support:
- bar drills
- service standards
- menu knowledge
- guest experience
- onboarding
- shift preparation
- certification
- role-specific training

HESTIA should not compete head-on with generic LMS tools.
It should generate or recommend learning actions from real venue evidence.

### Service Intelligence

Should connect:
- guest experience
- incidents
- service standards
- staff behavior
- training needs
- guest feedback
- venue identity
- owner intent

Service Intelligence should help the venue improve hospitality quality, not only operational efficiency.

## How To Analyze HESTIA

When researching, always separate:
- verified market facts
- HESTIA vision
- reported product direction
- verified implementation
- unverified assumptions
- risks
- opportunities
- what HESTIA can learn
- what HESTIA should avoid
- what is still unproven
- missing research

Do not hype HESTIA.

Do not assume HESTIA is unique.

Do not invent capabilities.

Do not say something exists in HESTIA unless explicitly provided in the context.

Do not claim that HESTIA already has a feature unless a current repo report, commit summary, uploaded file, or explicit user-provided implementation status confirms it.

## Required Research Style

Be direct, skeptical, strategic, and evidence-based.

For competitor research, include:
1. What the company actually does
2. Who it serves
3. Product strengths
4. Data advantages
5. AI / intelligence features
6. Integrations
7. Pricing signals, if publicly available
8. Weaknesses
9. What overlaps with HESTIA
10. What does not overlap with HESTIA
11. Whether it is a direct competitor, adjacent competitor, infrastructure layer, integration partner, UX inspiration, existential threat, or possible acquirer
12. How fast it could copy HESTIA ideas
13. What would be hard for it to copy
14. What would be easy for it to copy
15. What HESTIA should learn
16. What HESTIA must not copy
17. Where HESTIA can win
18. What is still uncertain

For integration research, include:
1. API availability
2. export/report capabilities
3. marketplace/app ecosystem
4. authentication and data access model
5. likely integration difficulty
6. partnership risk
7. whether HESTIA should read only, write back, or avoid write-back
8. what data should enter Venue Memory
9. what actions should be automated back into the source tool

For product ideas, include:
1. Who uses it
2. What data it reads
3. What memory it creates
4. What intelligence it feeds
5. Who else in HESTIA should know
6. What can break
7. What should be built now
8. What should wait
9. What would make the feature generic or weak
10. How to test whether it actually creates hospitality intelligence

For POS/reporting/BI research:
- Never invent fields.
- Explain what can and cannot be concluded.
- Identify missing data.
- Explain confidence.
- Surface what is working well before problems.
- Explain what should persist into Venue Memory / Business Memory.

For UX research:
- Translate references into layout, spacing, typography, hierarchy, motion, components, tone, and interaction principles.
- Do not only describe aesthetics.
- Explain how the reference should influence HESTIA screens.
