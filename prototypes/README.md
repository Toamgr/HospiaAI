# HESTIA Prototypes

This folder contains non-production design and interaction references.

Prototypes may contain hardcoded, fictional, demo, or exploratory content. Prototypes are not production UI. Prototypes are not canonical doctrine. Prototypes must not be wired directly into the app.

Production implementation must pass the HESTIA Skill Pack.

Owner Threshold production work must use:

- real auth/session/venue state
- real venue signals only
- provenance
- confidence
- role access
- venue boundaries
- human approval for high-impact meaning
- reduced motion
- mobile fallback

Hardcoded venue names, faculties, demo signals, fake urgency, and fake operational observations must be removed or replaced with real sourced data before production.

`owner-threshold.html` is a prototype reference for atmosphere, pacing, and threshold language only.
